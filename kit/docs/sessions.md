# 세션 나누기 — 관리자와 작업 세션

일이 커지면 한 대화에 다 담지 않는다. 대화가 길어질수록 앞의 맥락이 흐려지고, 생성 시험이 짓는 대화의 맥락에 오염된다.

## 역할

| 세션 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **관리자** (디자이너가 늘 여는 대화 하나) | 빈칸 지도 보기 · 무엇을 할지 정하기 · 작업 세션에 일 나누기 · 결과 확인 · 결정 기록 | 직접 많이 고치지 않는다 |
| **작업** (일마다 하나) | 정해진 한 가지 — 「값 들여오기」 「목록 부품 셋」 「화면 패턴 초안」 | 다른 작업의 파일을 고치지 않는다 |
| **피그마** (필요할 때 하나, 오래 둔다) | 피그마 읽기 · 키스크린 내보내기 · 피그마와 원천 맞대기 | 원천의 결정을 내리지 않는다 |
| **생성** (시험마다 새로) | 지침 파일만 읽고 화면을 만든다 · 짐작한 것을 적는다 | 원천을 고치지 않는다 · 짓는 대화의 맥락을 받지 않는다 |

## 넘기는 법

- 관리자 → 작업: 한 문단 — 무엇을 · 어느 폴더 · 끝난 모습 · 정해진 것과 물어야 할 것.
- 작업 → 관리자: 끝 보고(바뀐 것 · 정한 것과 누가 · 빈칸 지도의 변화 · 남은 것).
- 함께 보는 메모는 `notes.md` 하나 — 지금 진행 중인 작업 · 막힌 것 · 다음. 관리자가 정리한다.

## 같이 고치지 않는다

두 작업 세션이 같은 파일을 고치면 서로 덮어쓴다. 나눌 때 폴더(컴포넌트 하나 · 지침 묶음 하나) 단위로 겹치지 않게 나눈다.
`design/map.yaml` · `reading.md` · `ds.config.yaml` 은 관리자만 고친다 — 구조가 바뀌는 파일이다.

## Claude Code 에서

- 관리자 대화에서 「이 일은 따로 세션으로」 라고 하면 새 세션을 연다(데스크톱 앱은 세션을 옆에 나란히 띄울 수 있다).
- 생성 시험은 서브에이전트로 충분하다 — 지침 파일 경로만 넘긴다(`ds-generate`).
